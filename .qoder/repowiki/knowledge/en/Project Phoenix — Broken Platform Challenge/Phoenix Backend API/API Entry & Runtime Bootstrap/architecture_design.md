Four entry-point files form a thin bootstrap layer with a clear dependency direction: `config.ts` is the root of configuration (Zod schema over `process.env`, cached singleton via `getSettings()`), `db.ts` owns the Mongoose connection and exposes `connectDb`/`disconnectDb` plus an `ALL_MODELS` registry used by model initialization, `app.ts` constructs the Express application — disabling `x-powered-by`, enabling trust-proxy, mounting CORS from settings, then registering routers in order (`health`, `auth`, `workspaces`, `projects`, `tasks`) before JSON parsing, a `notFound` catch-all, and `errorHandler`. `server.ts` is the process entry point that calls `getSettings()`, `connectDb()`, then `createApp().listen(...)` on `127.0.0.1`, and installs `SIGTERM`/`SIGINT` handlers that close the HTTP server and disconnect the DB before `process.exit(0)`. Routers and models live outside this module; this scope only wires them together.
