Two thin Express routers (`projects.ts`, `tasks.ts`) expose REST endpoints under `/api/workspaces/:workspaceId/projects` and `/api/projects/:projectId/tasks`. Each route composes shared middleware from `../lib/auth` (`requireUser`, `currentUser`, `getProjectForUser`, `requireMember`), `../lib/http` (`asyncHandler`, `parseBody`, `parseId`, `HttpError`), `../lib/schemas` for request validation, and `../lib/serialize` (`projectOut`, `taskOut`) for response shaping. The data layer is three Mongoose models in `models/`: `Project` (scoped by `workspace` with an index), `Task` (scoped by `project` with a composite index on `{ project: 1, createdAt: -1, _id: -1 }`), and `CreditLedger` (append-only audit trail of credit deltas keyed by workspace plus a unique partial index on `idempotencyKey`). Dependency direction is one-way: routes depend on models; models have no cross-imports. Task creation is the only write path that mutates both `Workspace.credits` and `CreditLedger`, and it supports idempotent retries via the optional `idempotency_key` header.
