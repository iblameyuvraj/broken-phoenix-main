The `src/app.ts` factory (`createApp`) is the single wiring point: it instantiates Express, applies global middleware (CORS from `getSettings()`, JSON body parser with 100kb limit), mounts routers in a fixed order (`health` → `auth` → `workspaces` → `projects` → `tasks`), then installs `notFound`/`errorHandler` catch-alls. Cross-cutting concerns live under `src/lib/` — `config.ts` centralises env validation consumed by every route; `db.ts` provides the shared Mongoose connection; `http.ts` supplies `errorHandler`/`notFound`; `auth.ts` exposes bearer-token verification used by the domain routers; `schemas.ts`/`serialize.ts` provide Zod schemas and response serialization reused across models and routes. Domain routers (`routes/auth.ts`, `routes/projects.ts`, `routes/tasks.ts`, `routes/workspaces.ts`) each own their Mongoose models under `models/` and are mounted as Express routers, keeping per-resource state isolated while sharing the DB connection and auth middleware.
