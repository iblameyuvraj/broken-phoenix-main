Pure configuration module with no application code. `pipeline.yml` defines a linear GitHub Actions workflow triggered on push to `master`, composed of five jobs: `backend` (Node 16 + MongoDB service, typecheck + test), `frontend` (Node 16, build), `e2e` (starts both apps from `phoenix-backend` / `phoenix-frontend` in the background, then runs `scripts/smoke.sh`), `deploy` (Vercel CLI deployment gated on `refs/heads/main`), and `verify` (smoke against production). The smoke script is a standalone bash entry point taking backend/frontend URLs as arguments and asserting `/health`, the frontend root, and a login POST return success by printing `SMOKE OK`. Secrets (`VERCEL_TOKEN`, `VERCEL_ORG_ID`, project IDs) and variables (`BACKEND_URL`, `FRONTEND_URL`) are consumed from GitHub repo settings; there is no local build or install step beyond running the smoke script directly.
